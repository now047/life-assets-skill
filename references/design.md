# ライフ資産 設計書（汎用版 v0.1）

人生の充実度を、金融資産と並ぶ「もう一つの残高」として見える化するための設計。
目的は残高を貯め込むことではなく、お金・時間・健康を、幸福への変換効率が高いものに振り向けた状態で人生を終えること。

## 1. 基本構造

```
ライフ資産 L = 金融資産 F + 非金融ライフ資産 N
非金融ライフ資産 N = 健康資産 H + モノ資産 G + 体験・思い出・幸福資産 E + 学び資産 S
```

- 金融資産 F は額面どおり（家計アプリの純資産など、実績値と一致させる）。
- 非金融の各資産は「イベントの台帳」で管理する。各イベントは〔取得額・取得日・半減期〕を持ち、残存価値は時間で減っていく。

```
残存価値 = 取得額 × (1/2) ^ (経過日数 ÷ 半減期)
```

- 半減期方式は「幸福はじわじわ薄れる」感覚に合い、計算が単純で変数調整がしやすい。

## 2. イベント別ルール

### E1. 購入 — 変換であって収入ではない

モノの価値は2成分で考える。「もとの価値」はモノ自体の価値、「積み上がる価値」は使って得た幸福の価値で、置き場所が違う。

```
購入時：
  F -= P（実績）
  G += P        …… 「もとの価値」。購入価格そのまま（等価変換）
棚卸し時（年1回）：
  E += U        …… 「積み上がる価値」。その年に利用して得た価値を金額で申告し、幸福の側（E）に計上
```

- 購入時点で、そのモノを管理対象とするか判断する。管理対象にしたモノだけを購入品レジストリに登録し、もとの価値を計上する。管理対象外の購入は台帳に載せない。判断の基準は持たない（運用しながら決める）。
- もとの価値の半減期はカテゴリ別（初期値）：食品・消耗品 14日／嗜好品 30日／衣類・日用品 180日／道具・機材 730日／家具・家電 1460日。
- 積み上がる価値の入力は年1回の物品棚卸しのタイミングで行い、レジストリの一覧を見ながら各アイテムについて申告する。減衰は体験と同じ扱い（半減期は体験と同一、初期値 730日／記録あり 1460日）。
- 逓減変換と満足度係数は廃止した。旧方式では「逓減率 × 係数上限」の天井があり、高額な買い物ほど価格に届かなかった。2成分モデルでは、もとの価値が価格から始まり、想定以上の効果は積み上がる価値で表現できる。

### E2. 健康活動 — 将来の医療費削減見込みを収入に

```
H += 基礎額 + 距離・時間による加算
```

- ランの初期値：¥300／回 + ¥50／km（週2〜3回走る人で年間 ¥3〜5万規模の削減見込みに相当する置き方。調整対象）。
- 半減期は継続度で変える。直近28日の実施回数 n：n が 3以下 → 45日／4〜7 → 90日／8以上 → 180日。

### E3. 体験・家族イベント — 幸福度を金額換算

```
E += q × r_exp × m
```

- q は幸福度（5段階）、r_exp は換算レート（初期値 ¥5,000／点）、m は参加補正（家族と一緒なら 1.5）。
- 半減期は 730日。写真や記録を残したイベントは 1460日に延長。

### E4. 金銭で回復可能な損失

修理費などで元に戻るものは F の実費減少のみで扱い、N は変化なしとする。

### E5. 金銭で代替できない損失 — 減損

```
N -= d × r_loss
```

- d は深刻度（5段階）、r_loss は喪失の換算レート（初期値 ¥20,000／点。体験より重く置く）。
- 減損は時間で部分的に回復し、永久残存割合（初期値 20%）だけが残る。

### E6. 収入・利回り

F の実績どおり。N は変化なし。

### E7. 読書 — 学びの元本を積む

```
S += 読書分数 × reading_per_min（初期値 ¥10／分）
完読した本は1冊ごとにボーナス（初期値 ¥1,000、タイトルを台帳に残す）
```

- 根拠：知識・判断力の蓄積は、将来の稼ぐ力と失敗回避につながるという試算。単価は健康活動（ラン）の半分程度に置く。
- 半減期は読書 180日／完読 365日。知識は健康効果より残りやすいが、使わなければ薄れる。

### E8. 成長 — 学び残高への複利

「今日（昨日）の成長を一言で言えた日」は、その日時点の学び残高 × growth_rate（初期値 0.2%）を S に計上する。1日1回まで。

- 固定額ではなく元本比例にすることで、「昨日の自分に複利で上乗せされる」加速感を表現する。元本は読書（E7）で積み上がる。
- 言えない日・記録のない日は複利が付かないだけ（ペナルティはない）。放置すれば E7・E8 の残高も半減期で目減りする。

## 3. 変数の調整

- 変数は params.json に集約する。月次では変えず観測のみ、調整は四半期ごと。
- 調整したら履歴（いつ・何を・なぜ）を残す。

## 4. 計算例

- ラン 5km（習慣化している場合）：収入 ¥550、半減期180日。
- 道具 ¥30,000 を管理対象として購入：G に ¥30,000（もとの価値）、半減期730日。その年の棚卸しで「よく使った」として ¥15,000 を申告すれば、E に ¥15,000（積み上がる価値、半減期730日）。
- 家族イベントで幸福度 4：E に 4 × 5,000 × 1.5 = ¥30,000、半減期730日。
- 対人被害など深刻度 3 の喪失：N から ¥60,000 の減損、時間で部分回復。

## 5. 設計上の注意

- 金額換算は物差しであって真理ではない。判断と振り返りのための道具として使う。
- 記録が目的化すると幸福度自体が下がる。自動計上中心、手動は週数件まで。
- L に F を含む以上、L の最大化は貯蓄の最大化とは違う。晩年に F を体験や健康へ変換しきるほうが L 的には合理的になる含意を承知で使う。

## 6. 未決論点（v0.2 時点）

- **総額に占める N の小ささ**：F が大きいと N は総額の誤差に埋もれる。対象イベントの範囲と単価の妥当性は運用しながら見直す。当面の見せ方としては、ダッシュボードに「今月の新規計上」を併記してフローでも追う。
- **終わり方と生活防衛ライン**：残した F を一律に「変換し損ね」とみなすのは実感と合わない（家族に遺す価値がある）。あわせて、生活が成り立たなくなる水準まで F を下げることも避けなければならない。下限ライン（生活防衛分）を L の変換対象から外すか、遺す分を別枠にするかは要検討。
- **換算レートの校正方法**：レートが実感と合っているかの判定手順が未定。候補は、月末に感覚で挙げた幸福ベスト3と台帳の金額上位を照合する方法。運用しながら調整する。
- **健康収入の位置づけ**：医療費削減は統計上の見込みで、本人の財布への還元も検証も難しい。「将来得する金額」ではなく「習慣の蓄積」の度合いとして扱う格下げも含め、運用しながら見直す。
- **パラメータの what-if 表示**：アプリ（ダッシュボード）からパラメータを可変にして、変更でグラフがどう変わるか見える化する案。2026-11-09 時点では「やり過ぎ」として保留（データ量が少なく、変えてもグラフの変化が誤差に埋もれる）。四半期ごとの変数調整のタイミングで再検討する。それまでは、試したくなったら運用側が裏で別パラメータで再計算して見せる形で足りる。
